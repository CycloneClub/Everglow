# Phase 1 Plan 07 (Gap Closure) — ArmOfGiantTree Per-Player Charge & Server-Authoritative Shockwave

<objective>
Close the single blocking SC3 gap from `.planning/phases/01-item-inventory-completed-art-items/01-VERIFICATION.md` plus its two supporting warnings: the `ArmOfGiantTree` charge is global per-type state on the shared `ModItem` instance (CR-01), its shockwave damage is applied client-side only (WR-01), and the right-click ordinary swing is penalised by the charge floor (WR-02).

Purpose: roadmap SC3 requires that players can use every unblocked completed-art item with its documented effect. `ArmOfGiantTree` (texture present, unblocked) currently implements its core charged-smash effect with cross-stack and cross-player state, so the effect is incorrect. This plan is the smallest focused closure: move the charge to per-player synced state, make the shockwave server-authoritative, correct the swing penalty, and gate the result — per D-12 (completed-art design deviations are reconciled inside Phase 1) and D-10 (fix the deviation in place; no wholesale rewrite).

Output: `KelpCurtainPlayer.ArmOfGiantTreeCharge` with client-to-server sync, a rewritten `ArmOfGiantTree` that reads per-player state and delegates the shockwave to server authority, a new `ArmOfGiantTreeChargePacket` under the existing module `Netcode/` folder, a new structural gate `scripts/check-armofgianttree-charge.ps1`, the closure record in `01-DEVIATIONS.md`, and a green Release build with all existing Phase 1 gates.
</objective>

|----------|-------------|
| Client player input -> server authority | The owning client controls charge accumulation and sends it; damage application must be decided by the server, not the client. |
| Mod packet -> server ModPlayer state | `ArmOfGiantTreeChargePacket` is untrusted client input; the handler writes it onto the sender's own player only. |
| Item instance -> gameplay state | Gameplay state must not live on the shared per-type `ModItem` singleton. |
